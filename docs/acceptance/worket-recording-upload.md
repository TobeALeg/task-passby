# 记录时上传对话：验收记录

日期：2026-09-11。范围：源码与本机合成验收；未部署后台、未打包或发布桌面版本。

## 行为

用户主动开始记录后，在参与改进开启的前提下上传该记录已有和后续的用户消息、AI 回复，无需先沉淀。入口展示范围、用途、90 天留存以及退出和删除方式。后台新增“工作记录”样本与对话事件展示。原来的沉淀和复用样本协议继续兼容。

新授权版本为 `worket-recording-v1`。旧记录不会在升级、启动、打开或重新开启偏好时自动登记。主动恢复记录会重新授权该记录已有内容。完成、归档、取消记录及关闭参与改进停止上传并丢弃待同步正文；已发送内容可单独删除。保持单样本 1000 事件上限，达到上限后停止并显示错误；每个长消息分片也计入事件数。

## 证据

- `npm test`：109/109 通过。首次沙箱内运行因不允许监听临时 HTTP 端口受阻；沙箱外运行完成。新增 HTTP 集成测试使用临时数据库、独立安装身份和合成消息，验证记录即排队、离线重启后补传、增量消息、长文本重组、幂等、旧工作不自动登记、工具/推理/元数据排除、关闭后不再上传、重新开启不复活、主动恢复、取消与删除。供应商调用计数为 0。
- 协议测试验证旧授权版本不能授权新的记录范围，并拒绝推理事件和额外元数据。
- `node scripts/qa-recording-ui.mjs`：本机 Chrome 隔离会话，用合成 IPC 数据检查桌宠上传提示、退出后的“仅本机记录”、最近聊天、历史聊天入口；304×270 桌宠无裁切、448×760 面板无横向溢出、无页面脚本错误。实际查看了桌宠和面板截图。
- UI 报告及 4 张截图：`output/playwright/recording/`。此项不读取、不上传真实对话。

本次证明本机新版客户端逻辑与新版后台接口配合可工作，不代表线上新协议已生效或已有真实用户样本到账。下一次上线须部署支持 `RECORDING`/`MESSAGE` 的后台，再发布包含新记录入口的桌面包。
