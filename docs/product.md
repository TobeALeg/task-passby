# 产品定义：工作记录、接力与沉淀复用

> 2026-09-09 执行者接入设计：Codex、WorkBuddy 及后续执行者在记录与交接中具有同等地位；目标是统一记录入口，并把固定“交给 WorkBuddy”改为选择执行者。详见 [执行者平等接入方案](specs/executor-adapters-v1.md)。该方案尚未实现，下文现有行为不代表已经完成通用接入。

> 2026-09-08：本次以 [工作沉淀与复用 Spec v1](specs/work-distillation-v1.md) 为开发依据，已完成开发闭环与合成桌面验证；真实模型、身份接入和真实第二次工作仍待验收，详见 [验收记录](acceptance/work-distillation-v1.md)。下文“用户体验路径”“UX”“当前交付”描述现有记录与接力版本；末尾“下一阶段”描述目标行为，不能据此认定产品已经支持沉淀或托管模型服务。

## Production

### 用户是谁

在 Codex、WorkBuddy 等桌面 AI 应用中持续完成真实工作的个人用户。他们的工作散落在多轮 Prompt、Agent 回复、文件和操作中，并且不希望工作上下文被某个 Agent、应用、Skill 或会话锁定。

### 核心价值

用户在桌宠头顶展开的便利贴上点击“记录”后，系统识别前台 Codex 或 WorkBuddy 的工作上下文，把松散的 AI 协作过程记录并抽象为独立的 WorkInstance 和 WorkRecord。记录能够持续跨越不同 Executor 与 ExecutionEnvironment，并在需要时生成可直接接力的 Handoff Package。

产品核心是 Work Object：工作定义独立于执行者。事先定义工作的成本较高，因此从用户已有的真实工作记录进入。记录一方面支持继续同一项工作、交换 Agent，另一方面在用户主动选择“沉淀”后生成可复用的 WorkDefinition，用新输入开展下一次同类工作。未来传递给同事是独立的交接路径；并非所有工作都需要沉淀。

本次不新增 WorkPattern 实体；固定要求与参考方法先在工作定义中明确区分。术语见 [CONTEXT.md](../CONTEXT.md)。

### 产品原则

- 工作属于用户，不属于 Agent、应用、Skill 或会话；
- 用户主动触发后才记录；前台识别只读取应用身份和窗口标题，不读取或保存窗口内容；
- WorkInstance ID 是工作身份，对话 ID 只是来源引用；
- 原始档案与结构化 Work State 分离；
- 每条结构化信息必须可追溯到来源；
- 当前 Work State 的自动提取结果是可追溯的只读投影；用户回到来源对话修正事实后，再触发重新整理。下一阶段的 DefinitionDraft 可编辑，候选编辑不修改原工作状态和记录；
- 前台检测到的原始窗口标题不落盘；Codex 仅把 App Server 返回的应用总结标题作为可追溯来源保存，WorkBuddy 仅保存不可逆标题指纹用于重启后恢复关联；
- 工作记录与定义本地为主，云端处理须明确授权和范围。当前可选客户端模型配置与下一阶段 Worket 后台服务的数据边界不同，见 Spec；
- 完整记录不等于把完整聊天塞进目标 Agent；
- WorkDefinition、WorkInstance、WorkRecord、Executor 和 ExecutionEpisode 必须分离；
- 用户可以永久删除本工具持有的数据。

### 不做什么

- 不创建替用户自主执行工作的 Agent；下一阶段后台仅提供固定的模型分析流程；
- 不读取或推断 Agent 隐藏思维；
- 不持续记录所有桌面活动；
- 不自动判断并切分工作；
- MVP 不支持 Claude、ChatGPT 等其他 Adapter；
- MVP 不实现 WorkPattern 自动提炼与应用；
- 不做完整 Dashboard、云同步、多用户协作或全文件历史版本；下一阶段仅为用户确认纳入定义的固定资料保存本地版本副本；
- 不把 Codex、WorkBuddy 专属字段放入核心 Work State。

### 用户体验路径

1. 用户在 Codex 或 WorkBuddy 中进行工作；
2. 桌宠上方只在识别到支持的前台聊天时显示应用生成的会话标题，不把首次用户消息当标题；WorkBuddy 不提供标题时显示明确的通用标题；
3. 用户悬浮桌宠，头顶便利贴展开为“记录”；便利贴用于快捷记录当前工作；也可点击桌宠身体打开面板，逐项记录最近活动的聊天，或通过“记录沉睡工作”选择历史聊天；
4. 系统识别前台应用及当前聊天；Codex 容器没有窗口标题时，便利贴仅在唯一近期活动任务成立时绑定，多项同时活动的聊天在面板中分别提供记录入口；
5. Codex 在唯一标题匹配后立即导入完整既有历史，并用 App Server 的总结标题生成只读目标，不把首条消息或报错正文当目标；WorkBuddy 即使不暴露窗口标题也会显示通用前台对话气泡，在下一次真实提交中取得 session ID 后绑定并归档 transcript；无标题模式仅支持一份 WorkBuddy 活动记录，界面表达应用级记录状态，不伪造当前聊天的精确匹配；
6. 桌宠进入清醒状态，同一张便利贴变为“打开”，Source Archive 持续增量归档；
7. 用户通过便利贴或桌宠身体打开只读 Work State 面板；
8. 用户可以重新整理、从当前消息新建 Work、完成、归档或永久删除；
9. 工作完成或归档后保留当前聊天的“打开”入口，但气泡改为“已完成”或“已归档”，不再显示“正在记录”；
10. 用户点击“交给 WorkBuddy”；
11. 系统创建全新 WorkBuddy 对话，通过 MCP 交付 Handoff Package；
12. WorkBuddy 的后续协作继续写回同一个 WorkRecord；
13. 用户明确完成后停止自动写入；再次活动时选择继续原工作或新建工作。

面板的“最近活动”展示最近更新的五个 Codex 聊天中尚未建立记录的聊天；这表示近期活动，不声称聊天此刻正在运行。App Server 返回的 `notLoaded` 不代表沉睡。沉睡聊天通过历史列表按标题或项目筛选，并可加载更早的聊天。点击“开始记录”后导入完整可见历史，并独立持续同步后续消息；已有记录显示“打开记录”，不会重复创建或自动恢复已完成的工作。面板可见时每五秒刷新；后台每轮同步结束五秒后继续补采全部已授权的 Codex 活动绑定，单项读取失败不阻塞其他工作。发现聊天本身不自动归档。

## UX

桌宠圆点表达全部工作的采集状态：至少一项真实绑定正在记录时为绿色；只有待绑定工作时为黄色；没有有效采集时为灰色。该状态在重启后从本地记录恢复，不随选中工作或前台应用变化。气泡仍仅提示当前识别到的会话，待绑定时提示“请在 WorkBuddy 发送消息”。面板的“进行中”是工作生命周期分组，组内分别显示“正在记录”“等待发送消息”“已停止记录”。多项 Codex 工作可各自记录，WorkBuddy 无标题模式仍限制为单项活动记录。

### 设计原则如何回应以上要求

- **一致的品牌形象**：桌宠始终使用与 Dock 图标一致的圆土豆、右上便利贴和微笑表情；空闲时闭眼，其他状态睁眼，同时保留呼吸、搬运、提醒动画及对应体色和状态点，但任何状态都不改变笑嘴；
- **可发现的运行入口**：MVP 保留与桌宠一致的圆土豆加便利贴 Dock 图标；开发中固定使用 `scripts/run-latest.command` 启动当前源码；再次双击应用会把已有桌宠和侧边面板带回前台；
- **单次授权，不逐条打扰**：悬浮桌宠后点击便利贴即授权记录当前工作，不预览全部历史，也不要求逐项确认 Work State；
- **当前来源可见**：只在确认支持的前台聊天后显示窄气泡，标题直接使用来源应用生成的会话标题；
- **提取结果只读**：面板展示来源数量与提取结果，但不提供就地编辑或删除，避免投影与来源事实分叉；
- **交接是一键动作**：接入配置随 Worket 启动自动安装或更新，日常交接只需一个动作；
- **小而完整**：采用桌宠加轻量侧边面板，不建立复杂管理后台；
- **隐私可撤销**：用户可以完成、归档或永久删除本工具的数据；
- **来源清楚**：Work State 内容可以定位回原始消息，Codex 与 WorkBuddy 内容按 ExecutionEpisode 区分。

## MVP 完成定义

现有记录与接力版本以 [工作流规格](../workflows/record-and-handoff-work.md) 中的十四步真实桌面验收为标准。下一阶段另外必须通过 [沉淀 Spec](specs/work-distillation-v1.md) 中“真实记录 → 用户确认定义 → 新输入 → 新实例 → 外部执行 → 用户验收”的闭环。Mock、静态页面、健康检查或接口成功不能替代真实模型与桌面验证。

最近活动与沉睡聊天列表的每项来源均展示 Agent 名称和项目名；工作列表与详情展示当前执行 Agent，已结束的工作展示最后执行 Agent。WorkBuddy 尚未确认聊天时使用黄色“等待发送消息”，并明确说明尚未开始记录、需要在对应聊天发送消息；确认后自动切换为“正在记录”并移除等待提示。

面板按“最近活动 / 进行中 / 已完成 / 已沉淀”四个 Tab 分开，归档记录位于“更多”，默认打开“进行中”。最近活动只展示待记录的来源和“记录沉睡工作”入口，其余 Tab 只展示对应阶段的记录与详情。开始记录后跳转到对应工作阶段，完成或归档后跳转到新阶段；后台刷新保留当前 Tab。

### 桌宠自由移动

桌宠支持按住身体拖到任意显示器，单击仍打开面板；移动超过 5 像素视为拖动，松手不会打开面板。便利贴保持独立点击。位置在松手后保存，重启恢复；显示器移除或分辨率改变时回到可见工作区。

桌宠角色按原始尺寸的 75% 展示（身体 78 × 67.5 像素），五官、便利贴与点击区域同步缩放；对话气泡保留原字号。

## 用户主动沉淀与复用（开发实现，真实验收待完成）

2026-09-08 决策替代此前“归档为工作副本”的暂定方向：将可复用工作保存的能力命名为“沉淀”，并作为下一阶段核心功能。归档是独立生命周期操作，后续再设计，入口应置于次级区域；历史 ARCHIVED 记录不能自动变成已沉淀定义。

用户可以选择一条或多条已记录工作，点击“开始沉淀”后才触发抽象。系统检查多条记录是否同类，提取输入、交付、约束、验收标准与参考方法，保留来源并提出待确认问题。用户修改、确认后保存定义版本，在“已沉淀”中查看和使用；原记录不自动完成、归档或删除。

复用时，用户提供本次输入，创建新 WorkInstance，交给受支持执行者。旧客户、结论、完成状态与临时授权不默认继承。首次定义的完整价值必须通过第二次真实执行验证；生成候选文本不能单独算作完成。

抽象默认走 Worket 后台提供的模型 API，使用 Worket 的服务端凭据与额度管理，不使用用户的 Codex 订阅额度或 Codex App Server 发起模型任务。现有采集层读取 Codex 聊天的 App Server 不在本次替换范围内。

所选材料会经过 Worket 后台及模型供应商处理，产品不能宣传“全程离线”或“内容不经过 Worket 服务器”。未另行授权时仅暂时处理内容，运行/费用元数据与正文分开；2026-09-09 已实现单次范围授权的产品改进样本与反馈采集，保存 90 天，具体边界见 Spec。用户无需配置模型供应商 API Key；服务登录与用量方案在公开发布前落定。

状态整理、工作定义抽象是两种能力：交换 Agent 和未来传递给同事不触发沉淀。沉淀服务失败不妨碍已有记录、定义和交接材料的本地使用。

### 本次沉淀开发交付

用户在记录上选择“沉淀”或多选来源，在本地范围页明确勾选附件文本内容并确认云端处理后开始。候选按目的、输入、交付、约束、验收、方法和固定资料编辑，用户保存为不可覆盖的版本。固定资料存本地副本；复用时重新提供本次输入，默认不带旧成果。

新工作先保存，显示“尚未交给执行者”；复制或导出不表示接手。WorkBuddy 新对话收到真实 Hook session 后建立绑定，MCP 读取证据决定完整接手状态。本次成果由用户关联，并逐项选择通过或需要修改；只有全部通过才完成。服务故障不影响已有定义的本地使用。

当前提供管理员分配的 Worket 接入凭据入口。个人或团队管理员在本机后台填写供应商配置、测试连接、设置额度，签发和撤销桌面凭据；普通使用者无需接触供应商 Key。公开用户自助登录、HTTPS 部署和真实复用验收尚未完成，不能作为公开产品已经可独立使用的证明。

### 模型服务后台

后台通过浏览器打开，首次设置至少 6 位的管理员密码（本机使用支持简单数字密码），再填写 API 基地址、模型与 Key。“测试连接”只发送固定检测文本，成功后需明确保存；更换配置不需要重启服务。已有密钥不回显，更换供应商地址需重新填写密钥。

“Worket 接入”生成有期限、可撤销的接入凭据，用户复制到桌面 Worket；“运行记录”显示请求状态和调用次数，不展示工作正文。模型未配置时也能打开后台，发起沉淀会得到明确错误。当前后台只监听本机，远程使用需要单独部署 HTTPS；本机桌面接入使用开发模式。

## 本版本的数据积累目标：改进 Worket

2026-09-09 用户明确：当前版本采集数据的用途是改进 Worket。围绕主动沉淀与复用，积累所选工作材料、模型候选、人工修订和确认、复用及验收反馈，支持功能诊断、质量评测以及提示词、处理流程和模型版本比较。价值来自能复现问题、解释人工修正并验证后续改进的样本链。

改进采集必须作为可见产品能力说明范围、用途、期限及停止和删除方式，不能把现有模型处理授权自动解释为改进留存授权。新工作范围单独确认，未选择的历史聊天、附件和被动桌面活动不自动进入样本库。

**实现状态：**后台“改进样本”支持查看来源、候选原稿、用户修改、确认、复用验收，保存评审备注与删除；可暂停或恢复接收。桌面沉淀范围确认与创建复用工作页面分别提供默认不勾选的 `worket-improvement-v1` 授权，授权起保存 90 天。自动同步仅覆盖已授权的范围，不调用额外模型。复用首版只采集定义、非文件输入及逐项验收，交付物仅记录所选 ID，不读取文件正文。

“更多 → Worket 服务 → 改进数据”能查看同步状态、停止单个或全部样本的后续采集、删除后台样本。停止会丢弃待同步正文；已经发出的请求可能仍到达后台，彻底移除须使用删除。离线删除显示待确认，恢复原服务连接后完成。网络重试和应用重启不重复计数；服务或凭据变化时暂停上传。新范围仍需重新勾选，沉淀重试默认不加入改进采集。

当前交付通过合成数据、实际后台页面和打包桌面闭环验证。尚未导入本机真实样本，也未开展真实样本的版本效果对比；不得将自动采集可用表述为产品改进效果已验证。
